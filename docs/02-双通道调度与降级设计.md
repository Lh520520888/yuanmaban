# 02 · 双通道调度与降级设计

> 回答三个问题：① 要不要真机偏移 ② 是否设计为「内核走不通就走 B」③ B 是不是理论全覆盖。
> 所有结论均来自已拉取的源码，标注了文件位置，可复核。

---

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 需要真机偏移吗？ | **不需要「手工从真机提取偏移表」**。XPF 是运行时 patchfinding，给它 kernelcache 它就自己算。真机的作用从「提供偏移」变成「验证 patchfind 通过率」。 |
| 要设计 A→B 降级吗？ | **必须，且上游没有**。Dopamine 的 `DOExploitManager` 只按 priority 选**一个** exploit，失败即整体失败，无重试无降级。这层是我们自己的核心增量。 |
| B 理论全覆盖？ | **「可达性」全覆盖**（不依赖内核漏洞，无版本/SoC 天花板）；但「有效性」受 4 条非内核约束（授权 / keybag / 数据本身加密 / 枚举完整性），不是「装上就有明文」。 |

---

## 1. 偏移机制：不需要真机偏移，需要 kernelcache

### 1.1 XPF 是 patchfinding，不是偏移表

`01-越狱内核/XPF/src/non_ppl.c` 里每一个偏移都是「找字符串 → 回溯引用 → 解 adrp/add」的运行时计算：

```c
// XPF/src/non_ppl.c:4
static uint64_t xpf_find_pmap_image4_trust_caches(void) {
    ...
    uint64_t adrpAddr = pfsec_find_prev_inst(gXPF.kernelTextSection, found, 25, adrpInst, adrpInstAny);
    XPF_ASSERT(adrpAddr);
    return pfsec_arm64_resolve_adrp_ldr_str_add_reference_auto(gXPF.kernelTextSection, adrpAddr + 4);
}
...
xpf_item_register("kernelSymbol.pmap_tt_deallocate", xpf_find_pmap_tt_deallocate, NULL);
```

输入只有一个：**kernelcache 文件路径**。没有硬编码的「iPhone12,8 / 18.3 → offset 0xfffffff0070xxxxx」这种表（那是 lara 的做法，见 §1.4）。

### 1.2 未越狱真机上 kernelcache 只有一条路可走

`Application/Dopamine/Jailbreak/DOEnvironmentManager.m:684`：

```objc
- (NSString *)accessibleKernelPath {
    if ([self isInstalledThroughTrollStore] || getuid() == 0) {
        // 路1：本地 preboot kernelcache —— 需要 TrollStore 或 root
        return [[self activePrebootPath] stringByAppendingPathComponent:
                @"System/Library/Caches/com.apple.kernelcaches/kernelcache"];
    } else {
        // 路2：随包内嵌
        NSString *kernelInApp = [NSBundle.mainBundle.bundlePath stringByAppendingPathComponent:@"kernelcache"];
        if ([[NSFileManager defaultManager] fileExistsAtPath:kernelInApp]) return kernelInApp;
        // 路3：下载（未越狱设备唯一可行）
        if (grab_images(...) == false) return nil;
    }
}
```

- 路 1 **在我们场景不可用**（未越狱设备既非 TrollStore 也非 root）——这条分支必须保证不会误入；
- 路 2 内嵌会把包撑大且绑死版本，只适合给特定版本做兜底；
- 路 3 = `libgrabkernel2`（已拉到 `05-工具链/libgrabkernel2`），走 **AppleDB API 查 URL 后从苹果官方 CDN 下载**，README 明确「works for beta versions as well」，同时抓 `sptm.im4p` / `txm.im4p`。

**这就是我们项目唯一该走的路**：不连作者服务器，连苹果 CDN。

### 1.3 boot-manifest-hash 读取不需要 root

`BaseBin/libjailbreak/src/util.c:1420`：

```c
CFDataRef bootManifestHashData = IORegistryEntryCreateCFProperty(registryEntry, CFSTR("boot-manifest-hash"), NULL, 0);
```

IORegistry 只读属性，普通 App 沙箱内可读 → hex 化 → 交给 AppleDB 查对应 kernelcache 版本。**整条链路不触及任何特权**。

### 1.4 真正的门槛不是「真机偏移」，而是 XPF 版本适配

`XPF_ASSERT` 失败 = 该版本内核指令形态变了、上游 finder 没覆盖 → 偏移解析不出来 → exploit 拿不到地址 → 必失败。

所以版本天花板有两层，**第二层往往比第一层更早卡住**：

| 层 | 判定 | 谁决定 |
|---|---|---|
| exploit 层 | `DOExploit.isSupported`（Info.plist 的 min/max OS + 机型 include/exclude） | 漏洞本身的适用区间 |
| **偏移层** | XPF patchfind 能否在该 kernelcache 上成功 | 上游是否适配过这个版本 |

lara 的 `offsets.m` 打印过一句直白的话：`only supported offset for iOS 16.0 - 26.0.x` —— 偏移侧的覆盖边界。

**超出边界后要自己写 finder，那时候确实需要真机 kernel 来调**——但目的是「开发与回归验证 finder」，不是「提取一份偏移表」。性质完全不同。

### 1.5 工程要点

1. **按 boot-manifest-hash 缓存**：`Documents/kernelcache` 落盘，命中就不重复下载（Dopamine 已这么做，保留）；
2. **patchfind 有成本**：解 IM4P + 反汇编扫 text 段，真机上几十秒级，需异步 + 进度上报，别卡 UI 主线程；
3. **结果缓存**：`xpf_construct_offset_dictionary` 出的 xdict 落到本地，下次冷启动直接复用（同版本同 hash 偏移不变）；
4. **失败要可诊断**：`xpf_get_error()` 带上报错串回传，否则线上只看到「内核通道失败」四个字无法定位。

## 2. 降级路由：上游没有，我们必须自己写

### 2.1 上游的行为（反例）

`Application/Dopamine/Jailbreak/DOExploitManager.m:37`：

```objc
- (DOExploit *)_findPreferredExploitForType:(ExploitType)type {
    for (DOExploit *exploit in [self availableExploitsForType:type]) {
        if (!preferredExploit || exploit.priority > preferredExploit.priority) preferredExploit = exploit;
    }
    return preferredExploit;   // ← 只返回一个，无候选队列
}
```

`isSupported` 是**静态判定**（版本 + 机型 + 是否有 PPL bypass 需求），不是「跑一遍看成功没」。所以：

> 上游逻辑 = 静态筛选 → 选 priority 最高的那一个 → 跑 → 失败就整体失败。

拿到最高优先级不代表能跑通（PUAF 概率性失败、堆布局随机、设备状态异常都会失败）。**我们没有这个失败后手。**

### 2.2 我们要的调度层

```
                    ┌─────────────── 冷启动 ───────────────┐
                    │  读 boot-manifest-hash / SoC / 版本  │
                    └─────────────────┬───────────────────┘
                                      ▼
                          ┌──── L0 静态门 ────┐
                          │ DOExploit 规则判定 │
                          └───┬───────────┬───┘
                      有解   │           │ 无解 ────────────┐
                              ▼           │                 │
              ┌────── L1 内核尝试（带重试）──────┐           │
              │ 候选按 priority 排序，逐个跑     │           │
              │ 单发超时 T1，总预算 T2          │           │
              │ 失败 → 下一个候选              │           │
              └───┬────────────────────┬───────┘           │
            成功   │                    │ 全败              │
                   ▼                    │                   │
      ┌── L1.5 取钥匙（A 的核心产出）──┐  │                   │
      │  class keys / keychain-2.db   │  │                   │
      │  SB RemoteCall(securityd)     │  │                   │
      └───┬──────────────────┬────────┘  │                   │
      成功 │                  │ 失败      │                   │
           ▼                  └───────────┴───────┬───────────┘
   ┌──────────────┐                              ▼
   │ A 全量上传   │                    ┌── L2 通道 B（始终跑）──┐
   │ 明文 + 文件  │                    │ 用户态，秒级，无内核依赖 │
   └──────┬───────┘                    └───────────┬───────────┘
          │                                        ▼
          └──────────────► 合并去重 → 上传 → 写 done 标记
```

### 2.3 三条必须写进代码的规则

**规则一：B 不要排在 A 后面，B 应该先跑先传。**

B 是纯用户态、秒级、零风险，A 可能要几十秒到几分钟还可能失败。把 B 排在后面 = 把已经能拿到的东西押在内核成功率上。

正确顺序：**B 先扫 → 先传 → A 后台并行跑 → A 出结果再补传**。现包 `cold_wallets.zip` 走「HTTP before RC」就是这个思路，方向对，保留并把范围从冷钱包扩到全部目标。

**规则二：内核尝试必须串行重试，且失败要落盘。**

`multicast_bytecopy` 每次开机**仅一次机会**，失败即作废。所以：
- 候选队列按 priority 降序；
- 单发超时 T1（建议 60s），总预算 T2（建议 240s）；
- 每台机的尝试历史写本地状态文件（不要只放内存），重启后知道哪些已废；
- 全败 → 立刻转 B，不要空转等待。

**规则三：空结果不能写 done。**

现包有这个 bug（18.7.x 排查时发现）：空结果也标记完成 → 后续不再重试 → 永久零数据。修法：

```
done 的条件 = (成功上传 ≥1 个有效载荷) OR (尝试次数 ≥ N 且已判定该版本无解)
```

「有效载荷」要有内容校验（文件大小 > 阈值 / sqlite header 合法 / 非空行数），不是「文件存在」。

### 2.4 调度器骨架（ObjC，待实现）

```objc
// RouteOrchestrator.h
typedef NS_ENUM(NSUInteger, RouteState) {
    RouteStateInit = 0,
    RouteStateContainerDone,     // B 已完成并上传
    RouteStateKernelAttempting,  // A 尝试中
    RouteStateKernelOK,          // A 拿到钥匙

```

## 3. 通道 B 的边界：可达性全覆盖，有效性不是

### 3.1 为什么说「可达性」是全覆盖

B 的全部动作都在用户态：

- 枚举容器：`MCMContainerManager.containersWithClass:error:` / `containerWithContentClass:identifier:error:`
  （`03-容器与沙箱/iOS-Runtime-Headers/PrivateFrameworks/MobileContainerManager.framework/MCMContainerManager.h`）
- 取路径：`MCMContainer.url` / `.info` / `.uuid`
- 读文件：普通 `NSFileManager`

**没有任何一步需要内核读写、PPL 绕过、PAC 绕过。** 因此：

> 18.7.2+ / 26.1+ / A18 / A19 / M4+ —— 这些内核通道全军覆没的版本和机型，**B 不受影响**。

这就是 B 最大的战略价值：内核侧的版本天花板越收越紧，B 是唯一不会随 iOS 升级而失效的通道。

### 3.2 但有 4 条非内核约束会让它「跑得起来但没东西」

| # | 约束 | 表现 | 处理 |
|---|---|---|---|
| 1 | **授权层（客户端检查）** | 现场 18.7.x / 26.x 出现 `active_leases=3`、打开容器 `EPERM` | 我们靠伪装 bundle id 命中 MCM 客户端白名单；Apple 在这两个版本段收紧了。这是**待修的 bug，不是上游天花板**。需抓 `containermanagerd` 侧日志定位具体检查项 |
| 2 | **Data Protection / keybag** | 设备重启后未解锁一次（BFU）或锁屏状态下，`NSFileProtectionComplete` 类文件读不到 → 误判为「没装钱包」 | 扫之前先判 `protectedDataAvailable`，为 NO 就排队等 `UIApplicationProtectedDataDidBecomeAvailable`，不要立刻下结论 |
| 3 | **钱包数据本身是加密的** | 拿到 `main.sqlite3` 全密文，无 class keys 只能离线爆破 | B 全覆盖 ≠ 明文全覆盖。B 的价值是「至少拿到加密文件」，明文要靠 A 或服务端离线解 |
| 4 | **枚举与体积门限** | pass1/pass2 两轮仍可能漏；`skip oversized` 会跳过大文件 | 按钱包分级设门限，关键小文件（keychain 类、keystore）绝不能进 skip |

另有一条不算 bug 但统计上很显眼：**目标 App 从未启动过 = 容器是空的**。之前 OKX 那两台上传「35 张表全 0 行」就是这种情况，别跟解密失败混在一起看。

### 3.3 所以正确的表述是

- **B 的「能跑」**：全版本、全机型 ✅
- **B 的「有东西」**：取决于 1（授权）+ 2（keybag）+ 目标是否装了钱包
- **B 的「有明文」**：还得加 3（解密），通常要 A 配合或服务端离线解

## 4. 关于「这是利用项目，不是拿越狱机测试」

这点必须说清楚，因为它决定好几个改造点。

### 4.1 Dopamine 本身就是「面向未越狱设备的一键利用」

它不需要目标机已越狱 —— 它自己就是 installer。所以从它派生 ≠ 在越狱机上跑测试。真机在流程里的角色是 **QA/回归验证**：每个目标版本放一台，验 patchfind 通过率、exploit 成功率、RC 成功率、上传完整度。

### 4.2 但 Dopamine 代码里混了「越狱机快路径」，必须剥掉

`DOEnvironmentManager.m:686` 的 `isInstalledThroughTrollStore || getuid() == 0` 分支，以及 `activePrebootPath` 相关逻辑，是为已持久化/已 root 的设备准备的。在我们的 App 里这些恒为假，但**必须确认它们不会成为默认路径**——如果哪天误判，会走到读本地 kernelcache 的分支然后失败。改造点：直接删掉路 1，只留「内嵌 + 下载」。

### 4.3 目标不同：我们要的是「拿完就走」，不是「装一套越狱环境」

Dopamine 的成功判据是「越狱成功、launchdhook/jailbreakd 装好、用户能用 Substrate 生态」。我们要的是「静默取数据 → 上传 → 抹痕」。所以：

| Dopamine 有，我们**不要** | 原因 |
|---|---|
| `launchdhook` / `jailbreakd` 持久化 | 我们要的是一次性，持久化 = 留痕 + 被检测 |
| `update.m` 的 JB 更新逻辑 | 同上 |
| 完整的 tweak 注入生态（ElleKit/Substitute 全局注入） | 我们只需要最小能力：内核 R/W + 沙箱逃逸 + 一次 AKS 调用 |
| UI 与用户交互流程 | 我们有 Cover 假页面，不需要越狱 App 的 UI |

| Dopamine 没有，我们要**补** | 原因 |
|---|---|
| 采集清单（钱包/容器路径映射表） | 现包 `0x282600–0x282A20` 映射表那套 |
| 上传与重试、断网暂存 | 断网仍能利用，数据本地队列待补传 |
| 痕迹清理（`VarCleanRules.json` 那类） | 越狱项目不需要，我们需要 |
| **A→B 降级调度（本文 §2）** | 上游没有 |
| 冷启动一轮一次的约束管理 | multicase_bytecopy 等一次性利用的预算管理 |

一句话：**借它的「拿内核权限」前半段，砍掉它的「装越狱环境」后半段，补上我们自己的采集/上传/清痕/调度。**

## 5. 建议的验证矩阵（真机 QA 用）

真机不是用来提偏移的，是用来验证这条链的：

| 项 | 判据 | 通过标准 |
|---|---|---|
| kernelcache 获取 | 无 root 下 `grab_images` 成功 | 落盘且大小合理 |
| patchfind | `xpf_start_with_kernel_path` 返回 0 | 无 `XPF_ASSERT` 失败，xdict 完整 |
| exploit 成功率 | 同机型同版本连跑 10 次 | ≥ 7 次拿到内核 R/W |
| 钥匙获取 | class keys / keychain 可读 | 能解出 genp 的 v_Data |
| **降级正确性** | 人为让 A 失败（断网 / 不支持版本） | B 仍能出数据且上传，**不写空 done** |
| B 的 keybag 处理 | 重启后不解锁立即启动 | 不出「空钱包」，等待解锁后补扫 |
| 上传完整度 | 与设备上实际文件对比 | 关键文件 100%，无 oversized skip 误伤 |
