# 04 · 构建与联调手册

> 面向要在 macOS + Xcode 上把 `源码版/src` 真正编成 IPA 的人。
> 本文按"能跑起来"的顺序写，每一步都给出验证方法，失败时能定位到具体环节。

---

## 0. 前置条件

| 项 | 要求 | 验证 |
|---|---|---|
| 机器 | macOS + Xcode 15+ | `xcrun --sdk iphoneos --show-sdk-path` 有输出 |
| Theos | 已安装 | `echo $THEOS` 指向 theos 目录 |
| ldid | `brew install ldid` | `which ldid` |
| dpkg（打包 deb 可选） | `brew install dpkg` | — |
| 网络 | 能访问 `gh-proxy.com`（本仓库拉取方式） | `curl -I https://gh-proxy.com` |

Windows 侧只能跑 `tools/lint.py` 做静态自检，**出不了包**。

## 1. 编译依赖（必须先做）

```bash
cd 源码版/src/deps
make            # 全量：choma / img4 / xpf / grabkernel2
```

产物：

```
src/deps/build/ios/
├── libchoma.a
├── libimg4.a
├── libxpf.a
└── libgrabkernel2.a
```

单独重编某一项：`make xpf`、`make grabkernel2`。

**常见失败**

| 现象 | 原因 | 处理 |
|---|---|---|
| `xcrun: error: SDK "iphoneos" cannot be located` | Xcode 命令行工具未选 | `sudo xcode-select -s /Applications/Xcode.app` |
| `fatal error: 'choma/Fat.h' file not found` | ChOma 路径不对 | 检查 `01-越狱内核/ChOma/include` 是否存在 |
| img4lib 报 undefined `_vfs_lzvn` | 我们按上游排除了 `vfs_lzvn.c` | 确认 `deps/Makefile` 的 `IMG4_SRCS` 过滤仍在 |
| `ld: library not found for -lpartial` | libgrabkernel2 的预编译依赖 | 确认 `05-工具链/libgrabkernel2/_external/lib/ios/libpartial.a` 存在 |

> 注意：`01-越狱内核/XPF/external/img4lib` 最初是空的子模块占位，
> 本轮已从 `xerub/img4lib` 拉取补齐。若重新 clone 上游，需要再补一次。

## 2. 编译主工程

```bash
cd 源码版/src
make            # 或 ./build.sh
```

产出的 app 在 `.theos/_/Applications/OPENsrc.app`。

**这一步最容易踩的三个坑**

1. `vendor/*.m` 报错找不到 `OWVendorCompat.h`
   → Makefile 的 `-I$(CURDIR)/Headers` 缺失，或被 Theos 的 CFLAGS 覆盖。
2. `duplicate symbol _gXPF`
   → 说明同时静态链了 libxpf 又把 XPF 源码加进了 `OPENsrc_FILES`。只保留静态库。
3. `Undefined symbols: _task_self_trap`
   → `OWRCEntry.m` 用了 `mach/mach_traps.h`，需 iOS SDK；确认 `TARGET := iphone:clang:...`。

## 3. exploit framework 入包

```bash
# 1) 先用 Xcode 编一次 Dopamine（拿到带 exploit 的 app 产物）
#    DerivedData/.../Build/Products/Debug-iphoneos/Dopamine.app

./link_exploits.sh \
  ~/Library/Developer/Xcode/DerivedData/Dopamine-*/Build/Products/Debug-iphoneos/Dopamine.app/Frameworks
```

脚本做三件事：

1. 只拷 `Info.plist` 含 `DPExploitType` 的 framework（其余是越狱运行时，我们不要）；
2. **连带拷入 libjailbreak / libchoma / libxpf / libgrabkernel2**
   ——exploit 成功后原语写进的是 libjailbreak 的 `gPrimitives`，缺了它会出现
   "exploit_init 返回 0 但内核读写仍然拿不到"；
3. 用 `entitlements.plist` 重签主可执行。

验证：

```bash
ls .theos/_/Applications/OPENsrc.app/Frameworks/
# 应能看到 kfd/ClearSword/DarkSword/... 若干 .framework 以及 libjailbreak
```

## 5. 真机联调：按日志定位

日志由 `OWCommon` 落在 app 的 Documents，取回方式：

```bash
# 用任意能读 app 容器的方式导出 ow_route.log
```

### 5.1 关键行与含义

| 日志 | 含义 | 失败时查什么 |
|---|---|---|
| `设备 iPhone12,8 iOS 18.3 ... arm64e=1` | 设备画像 | arm64e=0 → A11 及更早，内核引擎加载不了，只有通道 B |
| `kernelcache: 走 libgrabkernel2 grab_images` | 抓 kernelcache | 若走"内置 AppleDB 下载"说明 libgrabkernel2 没链进来 |
| `偏移: 解析完成 base=0x... slide=0x...` | XPF patchfind 成功 | `patchfind 失败: ...` = 该版本 XPF 未适配，需自己写 finder |
| `内核: 尝试 kfd(smith) 第 1 次` | exploit 启动 | `无可用候选（静态门未过）` = 版本/机型不在 flavor 区间 |
| `primitives bind: gPrimitives=0x... -> OK` | 原语绑上 | `-> NONE` = libjailbreak 不在包里或 exploit 未真正填充 |
| `RC: attach securityd -> 0` | 注入成功 | 非 0 看 `rc_last_error` |
| `Keys: class keys 写入` | AKS 路径通 | 出现 `AKS selector 0xb 调用失败 kr=0x...` = selector 需按版本核对 |
| `Keys: 明文导出 N 字节` | SecItem 兜底通 | 出现 `提权失败` 看 `ow_escalate_last_error` |
| `阶段 -> done/failed` | 有效载荷非空/空 | 空结果**不会写 done**，下次启动会重试 |

### 5.2 三种"没数据"的区分

| 现象 | 判定 | 归属 |
|---|---|---|
| 包里没有 `keychain-2.db`，日志停在 exploit 失败 | 内核通道没通 | 版本/机型天花板或 exploit 未入包 |
| 有 `main.sqlite3` 但无明文，日志 `AKS selector ... 失败` 且没走兜底 | 钥匙层没打通 | AKS selector 未校准 |
| 钱包库能打开但表全 0 行 | 设备上没建钱包 | 与解密无关，别当 bug 查 |

## 6. 建议的验证顺序

1. **15.x–16.6.1** 的 A12/A13 机器：黄金区间，最容易一次跑通；
2. 确认日志出现 `primitives bind ... OK` + `偏移: 解析完成`；
3. 再看 `B: 取得 xxx.sqlite` 有没有内容（通道 B 应先出数据）；
4. 最后攻 `Keys:` 两行（明文）；
5. 18.7.x / 26.0–26.0.1 的 A12/A13 是上一轮分析出的"源码版净增区间"，单独验；
6. A14 及以上一律卡 ≤17.3.1，超过只能拿加密文件走离线爆破。

## 7. 每次改代码后

```bash
python 源码版/tools/lint.py     # Windows/macOS 都能跑
```

检查四项：括号配对、头文件声明与实现匹配、资源引用完整性、Makefile 收录一致性。
它能兜住的只是"明显写错"，真正的编译验证必须在 macOS 上做。
